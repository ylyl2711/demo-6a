# 双基地仓储库存与生产报工管理系统‑项目设计文档

> 项目面向：宁波汽车软轴软管有限公司 运行终端：Web管理后台 + H5移动端（手机浏览器访问） 技术栈
>
> - 后端：SpringBoot
> - Web前端：Vue
> - 数据库：MySQL
> - 移动端：H5 系统角色：**系统管理员、业务管理人员、车间操作工** 文档用途：毕业设计开发文档，承接需求规格说明书，指导概要设计、模块划分、数据库设计、接口设计，可直接复制至Typora

## 1 引言

本项目设计文档基于软件需求规格说明书进行编写，完成系统总体架构设计、模块划分、角色权限设计、数据库概要设计、目录结构设计、接口设计、部署设计。作为编码实现、单元测试的依据。

### 1.2 项目背景

宁波汽车软轴软管有限公司拥有宁波、合肥两大生产基地，主营汽车控制拉索总成、踏板总成等零部件。原有业务依靠纸质单据记录仓储、生产报工，存在批次追溯困难、呆滞物料无法预警、生产不良缺少统计、质检报告手工整理等痛点。 本系统采用Web+H5架构，实现双基地仓储管理、物料批次双向追溯、呆滞库存预警、H5车间报工、不良统计、质检报告导出，完成物料入库‑生产‑报工‑质检完整业务闭环。

| -------- | ------------------------------------------------------ |
| FIFO     | 先进先出，出库优先消耗较早入库物料批次                 |

## 2 总体设计

### 2.1 设计原则

1. **高内聚低耦合**：业务模块独立，模块之间通过接口交互。
2. **权限隔离原则**：三类角色严格权限隔离，车间操作工仅可操作本人工单。
3. **可扩展性**：字典统一管理，后续可扩展业务字段。
4. **复用性**：Web后台、H5移动端**共用同一套后端REST接口**，减少重复开发。
5. **数据安全**：关键业务操作全部记录操作日志，日志不可删除。

### 2.2 系统架构设计

系统采用前后端分离架构，分为四层：

1. **客户端层**
   - PC端：Vue实现Web管理后台，面向系统管理员、业务管理人员。
   - 移动端：Vue实现H5页面，手机浏览器访问，面向车间操作工。
2. **接口服务层**：SpringBoot提供RESTful接口，统一接收Web、H5请求；完成登录鉴权、权限拦截、参数校验。
3. **业务逻辑层**：各业务模块Service，实现仓储、批次、工单、报工、统计、文件处理业务逻辑。
4. **数据持久层**：MyBatis‑Plus操作MySQL数据库，完成数据增删改查。

> 架构说明：Web与H5只是前端展示不同，调用完全相同后端接口，依靠前端路由+后端权限控制区分功能。

### 2.3 系统模块总体划分

#### Web后台模块

1. 系统管理模块：用户管理、角色权限管理、基础字典、操作日志
2. 仓储管理模块：仓库档案、物料档案、入库单据、出库单据、批次追溯、呆滞库存预警、库存盘点、库存台账导出
3. 生产工单模块：工单创建分配、工单进度监控
4. 质量管控模块：工单质检审核、不良品分类统计、质检报告导出

#### H5移动端模块

1. H5登录模块
2. 我的工单模块：工单列表、工单详情
3. 工序报工模块：进度填报、照片上传、良品/不良品录入、提交完工申请

### 2.4 角色与权限设计

| 角色         | 使用端   | 权限说明                                                     |
| ------------ | -------- | ------------------------------------------------------------ |
| 系统管理员   | Web后台  | 仅操作系统模块：用户、角色、字典、操作日志；**不可操作仓储、工单业务数据** |
| 业务管理人员 | Web后台  | 全部业务权限：仓库物料出入库、批次追溯、呆滞库存、工单创建分配、质检审核、质量统计、报告导出 |
| 车间操作工   | H5移动端 | 仅查看分配给自己工单，工序报工、上传图片、录入不良、提交完工；不能访问仓储、工单创建功能 |

> 权限实现方式：后端接口拦截校验；前端菜单根据角色动态渲染。

## 3 模块详细设计

### 3.1 系统管理模块（Web后台）

1. **用户账号管理**
   - 功能：新增、编辑、启用/禁用用户，绑定角色。
   - 业务逻辑：用户名唯一；禁用账号禁止登录；区分三类角色。
2. **角色权限管理**
   - 功能：维护角色，为角色勾选菜单权限。
   - 业务逻辑：不同角色菜单权限固化；后端接口鉴权校验。
3. **基础字典维护**
   - 功能：维护不良原因字典、生产基地字典。
   - 业务逻辑：业务页面下拉选项读取字典，方便后续扩展选项。
4. **系统操作日志**
   - 功能：记录入库、出库、工单修改、批次变更操作；支持按时间、操作人筛选导出。
   - 业务逻辑：日志只新增，不允许删除。

### 3.2 仓储管理模块（Web后台）

1. **仓库与物料档案**
   - 维护宁波、合肥基地仓库信息；维护物料基础档案（原材料、半成品、成品）。
2. **物料入库管理**
   - 业务管理人员新增入库单据，必填物料批次号；保存后更新总库存与**批次库存**。
   - 单据只允许作废，不做物理删除。
3. **物料出库管理**
   - 新增出库单，系统自动FIFO优先展示最早未消耗完毕批次；扣减对应批次库存。
   - 校验批次库存，禁止超量出库。
4. **物料批次双向追溯**
   - 正向追溯：输入原材料批次，查询领用该批次所有工单、产出成品及成品批次。
   - 反向溯源：输入成品批次，查询生产耗用全部原材料与原材料批次。
   - 查询结果支持导出。
5. **呆滞库存预警**
   - 配置呆滞天数阈值；系统依据物料最后出入库时间计算呆滞天数；自动筛选呆滞物料列表。
6. **库存盘点、库存台账导出**
   - 录入实盘数量完成盘点，更新系统库存；支持导出Excel库存台账。
   - 库存低于下限自动进入库存预警列表。

### 3.3 生产工单模块（Web后台）

1. **工单创建分配**
   - 业务管理人员选择基地、产品、BOM、计划生产数量，选择操作工完成工单分配；工单状态初始为【待生产】。
   - 只有分配完成，操作工H5端才能看到该工单。
2. **工单进度监控**
   - 多条件筛选工单（基地、状态、操作工）；查看工序报工记录、生产照片、良品不良品统计。
   - 工单状态流转：待生产 → 生产中 → 待质检 → 已完成。

### 3.4 质量管控模块（Web后台）

1. **工单质检审核**
   - 仅待质检状态工单可以审核；填写合格/不合格、质检备注、质检不良原因；不合格可退回给操作工重新报工。
2. **不良品分类统计**
   - 聚合H5报工不良、质检环节不良数据；按不良原因（原材料缺陷/设备问题/人工操作问题）统计；输出饼图、柱状图；导出Excel。
3. **质检报告导出**
   - 仅已合格工单可导出质检报告文档，用于主机厂交付。

### 3.5 H5移动端模块

1. **H5登录**：仅车间操作工账号允许登录H5。
2. **我的工单**：展示分配给自己工单列表，支持按状态筛选。
3. **工单详情**：查看产品信息、工序加工要求。
4. **工序报工**：填写工序进度，上传现场照片，填写良品、不良品数量，选择不良原因；不良数量大于0必须填写原因。
5. **提交完工申请**：全部工序完成才可提交，提交后工单状态变更为待质检；提交后操作工不可随意修改报工记录。

### 关键业务约束

1. 物料入库生成新的`stock_batch`批次记录；出库修改对应批次剩余库存。
2. 呆滞库存：读取`warehouse_material`中`stagnant_day`阈值，对比`stock_batch`的`last_io_time`计算呆滞。
3. 工单状态严格按照：待生产→生产中→待质检→已完成流转，禁止直接数据库修改状态。
4. 操作日志表只做insert，不允许update、delete。
5. H5操作工提交完工后，报工记录禁止修改。

## 6 接口设计说明

1. Web管理后台与H5移动端**复用同一套REST接口**，接口鉴权统一在后端完成。
2. 接口分类：登录认证接口、系统管理接口、仓储管理接口、批次追溯接口、工单接口、报工质检接口、统计导出接口、文件上传接口。
3. 接口文档：项目集成Knife4j，自动生成在线接口文档，便于调试。
4. 返回统一格式：`{code:状态码,msg:提示信息,data:返回数据}`。

## 8 风险与注意事项

1. **批次业务风险**：入库、出库必须操作`stock_batch`批次表，否则批次追溯、呆滞预警功能失效。
2. **权限风险**：后端必须做接口鉴权，不能只依靠前端隐藏页面，防止越权访问。
3. **文件上传**：H5报工图片统一存储服务端，数据库只保存图片访问路径。
4. **工单状态**：严格控制工单状态流转，不允许随意跳转状态。

## 9 测试要点简述

1. 功能测试：覆盖用户故事全部业务流程：入库‑出库‑批次追溯、工单分配‑H5报工‑质检‑报告导出、呆滞预警、不良统计。
2. 权限测试：验证三类角色权限隔离，车间操作工无法访问仓储、创建工单接口。
3. 边界测试：批次库存不足出库校验；全部工序未完成不能提交完工申请。
