## 一、项目概述

面向宁波汽车软轴软管有限公司宁波、合肥双生产基地，采用 **Web 管理后台（Vue）+ H5 移动端（Vue）+ 统一后端（SpringBoot）+ MySQL** 的前后端分离架构。

- 三类角色：**系统管理员 / 业务管理人员 / 车间操作工**
- **12 张核心数据表**（9 张基础表 + 3 张新增表）
- 覆盖业务闭环：物料入库 → 生产领料出库(FIFO) → 工单分配 → H5 逐工序报工 → 提交完工 → 质检审核 → 成品入库 → 批次追溯 / 不良统计 / 报告导出

> 需求细节见 [需求文档](file:///c:/Users/pc/Desktop/demo-6a/doc/3.双基地仓储库存与生产报工管理系统 需求文档.md)，设计细节见 [项目设计文档](file:///c:/Users/pc/Desktop/demo-6a/doc/4.双基地仓储库存与生产报工管理系统 项目设计文档.md)。

## 二、关键决策（已确认，替代 v1.0 的"问题清单"）

| 编号 | 问题 | **最终决策** | 影响 |
|------|------|--------------|------|
| Q1 | 仓库/物料是否拆表 | **保持单表** `warehouse_material` | 9 张基础表不变，改动最小 |
| Q2 | BOM/工序如何落地 | **新增 BOM + 工序模板 + 工单工序 3 张表** | 表数 9 → 12 |
| Q3 | 前端技术栈 | **Vue2.7 + Element UI 2.15 + Vant2** | 与《设计文档》"Vue2"一致，不改表述 |
| Q4 | 报工/质检粒度 | **逐工序报工 + 整单质检** | `work_report_check` 一工序一条；质检按工单整单审核 |

### 2.1 最终表结构（12 张）

| # | 表名 | 中文名 | 状态 |
|---|------|--------|------|
| 1 | sys_user | 系统用户表 | 不变 |
| 2 | sys_role | 角色表 | 不变 |
| 3 | sys_dict | 数据字典表 | 不变 |
| 4 | sys_oper_log | 操作日志表 | 不变 |
| 5 | warehouse_material | 仓库物料表（单表） | 不变（Q1） |
| 6 | stock_batch | 物料批次表 | 不变 |
| 7 | stock_bill | 库存单据表 | **新增 `work_order_id`**（生产领料关联工单） |
| 8 | production_work_order | 生产工单表 | 不变（含成品批次 `product_batch`） |
| 9 | work_report_check | 报工质检表 | 一工序一条；质检字段整单共享 |
| 10 | material_bom | **BOM 表** | 新增：成品→原料用量 |
| 11 | process_template | **工序模板表** | 新增：产品固定工序清单 |
| 12 | work_order_process | **工单工序表** | 新增：建单时从模板复制的工单级工序 + 状态 |

> 新增表字段明细见 [共识文档（CONSENSUS）](file:///c:/Users/pc/Desktop/demo-6a/docs/双基地仓储库存与生产报工管理系统/CONSENSUS_双基地仓储库存与生产报工管理系统.md)。

### 2.2 关键业务约束（硬性）

1. 入库必录批次号，生成/更新 `stock_batch`；出库按 FIFO 推荐批次并扣减。
2. 生产领料出库 `stock_bill.work_order_id` 必填 → 打通"原料批次→工单→成品批次"追溯链路。
3. 工单状态机只在后端 Service 硬编码：`待生产→生产中→待质检→已完成`；不合格退回 `生产中`。
4. 操作日志只 insert，不 update/delete。
5. 提交完工后报工记录锁定，不可修改。
6. 不良数量 >0 必须选择不良原因。

## 四、里程碑划分与阶段目标

按依赖顺序划分为 6 个 Phase，每个 Phase 有明确验收节点。

```mermaid
flowchart LR
    P1[P1 数据库建表] --> P2[P2 后端框架+系统管理] --> P3[P3 仓储管理]
    P3 --> P4[P4 生产工单] --> P5[P5 H5报工] --> P6[P6 质量管控+统计]
```

| Phase | 目标 | 核心交付 |
|-------|------|----------|
| **P1 数据库建表** | 12 表建完 + 初始化数据 | `sql/init_table.sql`、`init_data.sql`、`test_data.sql` |
| **P2 后端框架+系统管理** | 三角色登录 + Knife4j + 权限 | 脚手架、统一返回、JWT 拦截、系统管理 4 模块、文件上传 |
| **P3 仓储管理** | 出入库/FIFO/追溯/呆滞/台账 | 档案 CRUD、入库、出库(FIFO)、批次双向追溯、呆滞预警、盘点、台账导出 |
| **P4 生产工单** | 建单分配 + 状态机 + H5 可读 | 工单 CRUD、BOM/工序模板、工序清单复制、状态机、进度聚合 |
| **P5 H5 报工** | H5 报工闭环 | H5 登录、我的工单、工单详情、逐工序报工、提交完工；报工质检接口 |
| **P6 质量管控+统计** | 质检闭环 + 图表 + 报告 | 质检审核、不良分类统计、统计导出、质检报告导出 |

## 六、开发规范约定

### 6.1 后端规范
| 项目 | 约定 |
|------|------|
| 包命名 | `com.project.stockwork` + 子包 |
| 数据库名 | `stockwork_db`（utf8mb4） |
| 表名 | 小写下划线，如 `sys_user`、`stock_batch` |
| 主键 | `id` bigint 自增 |
| 逻辑删除 | 不使用，单据用"作废"状态标识 |
| 接口路径 | `/api/{module}/{action}` |
| 返回格式 | `{ code: 200, msg: "成功", data: {...} }` |
| 日期格式 | `yyyy-MM-dd HH:mm:ss` |
| 金额/数量 | `BigDecimal`，`decimal(10,2)` |
| 事务 | 出入库、工单状态流转、报工+工序状态 加 `@Transactional` |
| 权限校验 | 自定义 `@RequireRole("ADMIN")` 注解 + 拦截器 |
| 文件存储 | 本地 `resources/static/uploads/`，返回 `/uploads/xxx.jpg` |
| 密钥管理 | 数据库/密钥置于 `.env`，**不提交 git** |

### 6.2 前端规范（Web + H5）
| 项目 | 约定 |
|------|------|
| 接口调用 | 统一 `request.js` 封装 Axios，拦截器自动加 `Authorization: Bearer xxx` |
| 路由守卫 | 未登录跳登录页；菜单按角色过滤 |
| 组件命名 | PascalCase |
| API 文件 | 按模块拆分 `api/auth.js`、`api/stock.js` |
| 环境变量 | `.env.development` / `.env.production` 配置 baseURL |

## 八、验收标准与演示路线

| Phase | 验收方式 | 通过标准 |
|-------|----------|----------|
| P1 SQL | DBeaver/Navicat | 3 脚本无报错；12 表齐全；管理员可登录 |
| P2 后端基础 | Knife4j + Postman | 三角色登录成功；接口返回 code=200 |
| P3 仓储 | Web 真实操作 | 出入库→FIFO→追溯→呆滞→台账 全跑通 |
| P4 工单 | Web + Postman | 建单复制工序；分配后 H5 可读；非法状态跳转被拦截 |
| P5 H5 | 手机浏览器 | 操作工登录→看工序→逐工序报工→提交完工→状态变待质检 |
| P6 质检 | Web | 质检审核闭环→图表正确→报告可导出 |

**最终演示路线**：

```
管理员登录 → 建业务人员账号 + 操作工账号
业务人员登录 → 录原料入库(宁波, 录批次) → 维护 BOM/工序模板
            → 创建工单(绑BOM, 分配操作工) → 生产领料出库(FIFO, 关联工单)
操作工 H5 登录 → 看工单/工序要求 → 逐工序报工(良品/不良/原因/照片)
            → 提交完工申请
业务人员 Web → 工单状态变"待质检" → 审核合格 → 成品入库(成品批次)
            → 批次追溯 → 查看不良统计饼图 → 导出质检报告
```
